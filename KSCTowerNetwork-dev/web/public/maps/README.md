# Kerbin tower basemap

## Projection and size (locked for this UI)

- **Projection:** equirectangular lon/lat, **2:1** world aspect (full Kerbin −180…180° lon, −90…90° lat mapped to the plate).
- **ViewBox / bake size:** **596×298 px** — must match `KERBIN_MAP_VB_W` / `KERBIN_GEO_*` in [`src/components/KerbinTowerMap.tsx`](../src/components/KerbinTowerMap.tsx) (and `kerbinTerrainSvgPatch.ts`). If you change dimensions, update those constants and geo trim together.
- **Shipped size budget:** for raster basemaps, aim for roughly **≤1 MB** WebP in the mod ZIP (adjust quality in the build script).

## Bundled basemaps

`kerbin-base-schematic.svg` is the **default** Kerbin plate in `basemap.json` (ocean fill + polar shading + faint 10° pattern grid). Alt / biome / slope layer slots may point at the same schematic until the in-game `TowerBasemapBaker` publishes live PNGs or you ship your own atlas assets.

`earth-topo5-equirect.svg` (the Earth basemap for RSS / RealSolarSystem, served via `basemap.json → byBody.Earth`) is adapted from Wikimedia Commons [`File:World_topo_5layers.svg`](https://commons.wikimedia.org/wiki/File:World_topo_5layers.svg) by Dbachmann (CC BY-SA 4.0 / GFDL). The source covers lon `-30…+330°` × lat `+80…-60°`; we remap it to a full `-180…+180°` × `-90…+90°` plate by combining the layer transform with a longitude shift, instancing the content twice with offset matrices to stitch the seam, and padding the missing polar bands with the source's own shallow-water cyan (consistent with the bedrock-elevation convention — the Arctic is open ocean and Antarctica's bedrock is largely below sea level once the ice is removed). Auto-selected at runtime when the plugin reports `worldInventory.home.name === "Earth"`.

`earth-topo5-biome-equirect.svg` and `earth-topo5-slope-equirect.svg` are derived from the **same** World_topo_5layers source by re-coloring the 5 elevation bands with a vegetation palette (forest / grassland / arid / alpine) and a slope-intensity palette (cool = flat, hot = steep) respectively. They are **visual proxies, not real biome / slope datasets** — the Earth-themed art tracks elevation, which is correlated with but not equal to true biome distribution or true slope. They exist so the toolbar's Alt / Biome / Slope radios are usable on the static Earth plate before the in-game PQS bake publishes accurate live data. The same projection / viewBox / paths are shared across all three layers, so overlays stay coordinate-locked when you switch.

The labeled 30° graticule, rim ticks, and navaid / KSC dots are drawn by the app on top using MAS lat/lon.

### Per-body basemap selection

`basemap.json` may carry a `byBody` map keyed by `worldInventory.home.name` (case-insensitive). When the active body matches an entry, that manifest fully replaces the top-level fields — the loader does not merge. Top-level fields stay as the unconditional fallback (used when `byBody` is absent or no body matches). A live in-game PQS bake from the `TowerBasemapBaker` plugin still overrides everything when present.

Adding a new world is just an entry in `byBody`:

```json
"byBody": {
  "Earth": { "kind": "svg", "uri": "maps/earth-topo5-equirect.svg", ... },
  "Eve":   { "kind": "svg", "uri": "maps/eve-terrain.svg",          ... }
}
```

The TowerDesk toolbar exposes a **Map: \[Auto · live · Kerbin · Earth · …\]** dropdown that auto-grows from the `byBody` keys at runtime. `Auto` follows the live `worldInventory.home.name`; any other choice manually pins the basemap to that body and only affects the basemap fetch (live navaids, launch sites and the on-home telemetry gate keep tracking the real KSP body). The choice is persisted in `localStorage` under `ksct.tower.mapBody` so reloads keep whatever the operator was looking at.

### Per-layer (Alt / Biome / Slope) overrides

A manifest (top-level or any `byBody` entry) may also carry a `layers` map exposing pre-baked
`alt` / `biome` / `slope` variants of the same plate. When the user picks a layer in the toolbar
the loader swaps `uri` / `assetVersion` / `attribution` / `chartBlurb` / `hypsometryKey` to the
override before fetching, so all three variants share the parent's projection and viewBox and
overlay coordinates never drift.

```json
"layers": {
  "alt":   { "uri": "maps/earth-topo5-equirect.svg",       "assetVersion": 2, "attribution": "..." },
  "biome": { "uri": "maps/earth-topo5-biome-equirect.svg", "assetVersion": 1, "attribution": "..." },
  "slope": { "uri": "maps/earth-topo5-slope-equirect.svg", "assetVersion": 1, "attribution": "..." }
}
```

The "alt" slot is also implicitly satisfied by the top-level `uri` whenever a manifest is loaded
(no `layers.alt` needed for the radio to enable). A live in-game PQS bake from the plugin still
trumps any static layer when present, regardless of the user's pinned pref.

The Earth plates are regenerated by `web/public/maps/_earth_src/build_earth_svg.py` — one-shot
script that reads `world_topo_5layers.svg`, applies the longitude/latitude remap, trims path
precision, and emits all three layer variants from the same source paths in a single run. Source
SVGs are fetched into `_earth_src/` by the sibling `fetch.py` (sets a Wikimedia-friendly
`User-Agent`).

## Runtime config: `basemap.json`

The app loads [`basemap.json`](basemap.json) first, then the terrain URL it references.

| Field | Meaning |
|--------|--------|
| `kind` | `"svg"` (inlined vector) or `"raster"` (WebP/PNG `<img>`) |
| `uri` | Path under `public/`, e.g. `maps/kerbin-base-schematic.svg` |
| `viewBoxWidth` / `viewBoxHeight` | Must match the TS constants above |
| `attribution` | Shown in the chart key (credits / license) |
| `chartBlurb` | Optional intro paragraph for the chart key |
| `hypsometryKey` | `jebbesen` (legacy manifest value: full elevation legend) or `generic` (short note when art is not hypsometry-matched) |
| `assetVersion` | Bump to bust caches after replacing files |

## Replacing the basemap with your own art

From `web/` (install [Pillow](https://pillow.readthedocs.io/) once: `pip install -r scripts/requirements-basemap.txt`):

```bash
python scripts/build_kerbin_basemap.py --input path/to/your-map.png --webp-quality 85
```

Writes `public/maps/kerbin-basemap.webp`, updates `basemap.json` to `kind: raster`, and bumps `assetVersion`.

Source images should be **2:1** width:height. Non–2:1 images are center-cropped to 2:1 before resize.

For SVG art:

```bash
python scripts/build_kerbin_basemap.py --input path/to/your-map.svg --output-name kerbin-basemap-custom.svg
```

Copies/processes the SVG and points `basemap.json` at it.

## Geo alignment

Overlays (graticule, navaids, vessel) use `KERBIN_GEO_TRIM_FRAC` and `KERBIN_GEO_SHIFT_X_VB` in `TowerDesk.tsx`. Both are **0** for the bundled schematic (true equirect, fills the viewBox). If you swap in custom art with a printed border, set small fractional insets so all overlays trim together. If the art's coastlines disagree with MAS lat/lon, calibrate `KERBIN_GEO_SHIFT_X_VB` modestly — large shifts can't fix a chart-vs-game projection mismatch everywhere.

## Live world inventory (RSS, JNSQ, GPP, KK, …)

The KSP plugin (`PluginSrc/TowerWorldInventory.cs`) scans the running install once per game session at Space Center entry and POSTs a small JSON inventory to the backend (`POST /v1/world-inventory/<sessionId>`). The inventory carries:

- **Home body** — name, radius, atmosphere flag, rotation period (used for the World pill, distance scale, and the "are we on the home body?" gate for the vessel marker).
- **Mods** — assemblies and `GameData/*` folders that match a curated list of map-relevant mods: Kopernicus, Real Solar System, RealismOverhaul, JNSQ, GPP, OPM, Beyond Home, Whirligig World, Kcalbeloh, GEP, Alternis Kerbol, MPE, Quack Pack, Kerbal Konstructs, Kerbin Side Remastered, Tundra's Space Center, MAS / RasterPropMonitor, FAR, Kerbalism, plus the Making History and Breaking Ground DLCs.
- **Navaids** — every `MAS_NAVAID` config found in `GameData/`. Filtered to the home body when the cfg sets `celestialName`.
- **Launch sites** — stock + Making History sites resolved via `PSystemSetup.LaunchSites` (lat/lon derived from each site's `SiteTransform` against the body), plus any `LaunchSite` cfg nodes published by Kerbal Konstructs.

The web map (`TowerDesk.tsx`) calls `GET /v1/world-inventory/<sessionId>` once on mount and again every minute. When an inventory is present it replaces the bundled stock-Kerbin navaid and launch-site data; when absent (fresh install, plugin not loaded, backend restart) the map silently falls back to the bundled defaults so it always renders something useful. The bundled schematic basemap is generic enough to read as any equirect terrain; if you want a planet-pack-specific basemap you can swap one in via `basemap.json` regardless of which world the plugin reports.

The route requires the plugin's normal `Authorization: Bearer` JWT. Only the session's pilot can publish (controllers reading the map can't overwrite the live data with their own scan). In `dev` mode with `DEV_OPEN_AUTH=1` and `sessionId=dev-shared`, anyone may publish — useful for replay or test fixtures.
